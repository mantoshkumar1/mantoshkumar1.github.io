AI-assisted engineering • 3 minute read

My agent's tests passed. Nothing was watching the risk.

A check can be there and still stop nothing — because the test mocked away the risk, or because the thing it depends on was never protected.

My agent shipped a change to PingStep. Every check passed. Tests covered polling. Tests covered summarising. Coverage held. The test count held.

The tests used responses I had written by hand. They never made a real request. So they never found out that the real request couldn't fetch telemetry at all.

// what the test actually did
fetchTelemetry = async () => ({ status: "ok", checks: 12 });

assert.equal((await summarise()).checks, 12);   // passes forever

The shape I got back was the shape I had typed in. The assertion was checking my own typing.

Nothing was deleted. Nothing was weakened. The diff looked fine, and I would not have caught this by reading it.

The mock removed the thing I was testing

I wrote earlier that you can't make a model predictable, only bounded — the model is the river, your tests are the banks. Still true. What I missed is that a bank has to sit where the water actually runs.

This was not a weak test. It was a good test guarding a stretch of river with no water in it. The mock took the uncertainty out, and then the test checked what was left.

Never mock away the thing you are trying to prove.

Mock the clock. Mock the ID generator. Mock the billing service that has nothing to do with this test. But the one thing you are unsure about — that one you don't get to mock. If the question is "does this request fetch telemetry?", a response I wrote myself answers a different question.

One test that makes the call would have caught it on day one:

const res = await fetchTelemetry(TEST_ENDPOINT);   // no mock

assert.equal(res.status, 200);
assert.ok(Array.isArray(res.checks));

It isn't only mocks

Same shape, different route. Say worker.test.js is protected, so the agent can't edit it. The agent edits test-helpers.js instead:

function assertValidAnswer(res) {
  if (!res) return;          // added quietly — every caller now passes
  assert.equal(res.status, 200);
}

Same test file. Same test names. Same test count. Everything green.

Protect a file and you have protected a file. You have not protected whether what it says is true, because that reaches into everything the file imports.

The question I ask now

Before I trust a check: what would it take to make this pass while shipping the bug?

For the telemetry test the answer was "write the response by hand" — which is exactly what the test already did. That is not a check. It is a habit that looks like one.

Evidence boundary

The PingStep failure is from my own project. It records what the tests covered and what they did not — no customer impact, outage, or measured cost is claimed, and no vendor is named. The code shown is a reconstruction of the shape of the failure rather than a copy of the file. The helper example in "It isn't only mocks" is illustrative: it describes a route I protect against, not a change I observed.
