When a product builds the system that will maintain it

PingStep did more than reveal what an AI coding control plane should do. It became the real workload from which DogBuild could be designed, tested, and eventually extracted.

The unusual part is the direction of travel: DogBuild is being born inside the product it is intended to maintain.

The direction changed

I first described DogBuild as the missing message bus between independent AI coding agents. That was accurate, but incomplete. The deeper problem was never only transport. It was control: who may act, which evidence is current, whether a reviewer is independent, when a changed commit invalidates a verdict, and exactly where the human must return.

Those questions did not appear in a whiteboard exercise. They appeared while building PingStep ↗ with multiple AI workers. Every repeated coordination failure became a candidate product requirement for DogBuild.

PingStep is not merely DogBuild's first integration. It is the environment that is teaching DogBuild what it has to become.

The bootstrap loop

This resembles a self-hosting compiler: build the first version with the tools available, prove it on real work, then let the new system participate in maintaining the system that produced it.

This is self-hosting, not circular coupling

Putting the first kernel under a dogbuild/ directory in the PingStep workspace does not mean mixing two products. It means using the closest real laboratory while preserving an extraction boundary from day one.

  • DogBuild core stays generic. It knows tasks, roles, evidence, commit identity, authority, and state transitions. It does not know PingStep's pricing, monitoring semantics, or customer data.
  • The PingStep adapter stays specific. It declares the board, workers, review gates, launch boundaries, and project commands.
  • PingStep runtime stays independent. The website, worker, database, and production path do not import or call the control plane.
  • Extraction is a testable milestone. A clean boundary is proven when the same kernel can coordinate another repository by replacing configuration rather than rewriting logic.

Why a real parent matters

A generic orchestrator designed in isolation can easily optimize for demos: create a task, call an agent, collect an answer. A real product supplies the failures the demo omits.

  • A worker says it is finished, but the pull request head changed afterward.
  • A reviewer finds a problem, the producer repairs it, and the central board still points at the old finding.
  • Two useful tasks are available, but doing both would invalidate the frozen launch candidate.
  • The founder is unavailable, yet only one action—not the entire program—requires founder authority.
  • A token budget changes which model should implement the next untouched artifact, without allowing a producer to approve its own work.

These are not edge cases around the system. They are the system. PingStep provides them at full fidelity, with consequences serious enough to force precise contracts.

What DogBuild must learn before it leaves home

The first useful version is not “agents can comment on GitHub.” It is a small control plane that can reconstruct truth without trusting narration.

  1. Observe: read issues, pull-request heads, commits, checks, reviews, and immutable event IDs.
  2. Reconcile: compare those facts with the declared board and detect stale or contradictory state.
  3. Route: publish exactly one current task and a short, safe fallback queue for each worker.
  4. Fence: invalidate evidence when the head, base, test meaning, or authority changes.
  5. Escalate: stop only the action that needs human judgment and continue disjoint work safely.

GitHub remains the public ledger and event source. DogBuild adds derived state and policy; it should not invent a second truth that operators must reconcile by hand.

The inversion

At the beginning, PingStep needs people and general-purpose agents to build DogBuild. If the architecture works, the dependency inverts: DogBuild watches PingStep's repository, supplies bounded work to interchangeable agents, verifies exact-head evidence, and returns only genuine product or authority decisions to the founder.

That does not remove the human. It moves the human to the decisions where human judgment is actually valuable.

The goal is not a product that builds itself. It is a product whose engineering system knows when it can continue safely—and when it must stop.

What exists now

This architecture is being recorded as an implementation direction, not presented as a completed platform. The public DogBuild repository ↗ contains the current project and its history. The first useful delivery target is a narrow GitHub App that observes repository events, reconstructs current state, and prepares bounded work without gaining merge or deployment authority.

The relevant implementation contracts are public in DogBuild issue #134 ↗ and the reconciliation follow-up in issue #135 ↗. PingStep's source repository is private; no claim here depends on readers accepting inaccessible code as proof.
