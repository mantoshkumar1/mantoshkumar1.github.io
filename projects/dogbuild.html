DogBuild

An experimental deterministic control and orchestration layer for coordinating multiple AI coding agents through GitHub and curated MCP interfaces—removing the need for humans to manually relay context between implementation, review, and routing.

Currently under active development and not yet a production-ready autonomous-agent platform.

The Problem

When coordinating multiple AI agents across different vendors (Claude Code for implementation, ChatGPT for review, etc.), without a control plane, the human becomes the message bus:

  • Implementation complete → human copies result to reviewer
  • Review findings → human carries feedback back to implementer
  • Every round of fixes requires manual relay

That manual relay is structural friction, not a habit to optimize. DogBuild explores how intent, authority, evidence, routing, and handoffs can become deterministic and auditable instead.

Current Architecture

DogBuild is built on lived dogfooding, not theory. Here's what's real as of September 2026:

  • GitHub-first evidence: All project state, decisions, and evidence live append-only on GitHub. Chat is a wake interface only; the repository is the durable source of truth.
  • Three-server MCP portal: A Cloudflare-hosted gateway providing curated, bounded GitHub access through validated MCP servers. 53 tools classified and independently reviewed.
  • Exact-head CI aggregation: Read-only capability to observe complete CI state for any exact commit SHA, including post-merge push workflows (not just PR-triggered runs).
  • Deterministic routing: DogBuild itself makes no product decisions. It enforces boundaries—founder authority, append-only evidence, exact identity validation—while workers do their work.
  • Authority tiers: Founder → Strategy → Workers. The human approves anything irreversible (merge, deploy, delete, spend). Strategy routes work and reconciles evidence. Workers are bounded to assigned tasks.

Key Design Principles

DogBuild operates on these settled principles:

  • GitHub is the durable source of truth. Chat is a control/wake interface only.
  • DogBuild contains no AI and makes no semantic decisions. Workers and humans make product calls.
  • Strategy carries founder intent. The human decides anything irreversible.
  • Workers do not self-start or broaden authority. Every task is explicitly bounded.
  • Evidence is append-only. Corrections supersede earlier evidence without rewriting history.
  • Exact identity is revalidated before writes. Repository, task, role, generation, target, and requested effect are all fresh-validated.
  • Missing or conflicting evidence fails closed. When truth is unclear, the system stops rather than guessing.
  • Implementation and review are separate roles. The same session does not both implement and approve.
  • Infrastructure-critical work receives adversarial testing. Happy-path tests are insufficient; fault-injection, security-negative, and high-volume cases must be proven.

What This Is NOT (Yet)

  • Not a production-ready autonomous-agent platform
  • Not a claim of exactly-once distributed execution
  • Not an unrestricted GitHub administration layer
  • Not a replacement for repository protections, CI, or human judgment
  • Not a deployed fourth MCP server
  • Not a finished commercial product

Roadmap

In order of planned execution:

  1. Correct exact-SHA CI aggregation proof — restore tests, model production semantics, prove fault-handling
  2. Reconcile comment-policy tool — bounded correction or explicit scope decision
  3. Least-privilege identity and scope — restricted credential separate from founder account
  4. Pre-write authorization gateway — revalidate exact authority before every mutation
  5. Complete onboarding and session conformance — reusable entry points for blank sessions
  6. Deploy with explicit authorization — founder-only gate with rollback evidence
  7. Repair and re-admit listener — address safety findings before real agent invocation
  8. Prove end-to-end workflow — task → plan → branch → implementation → review → merge
